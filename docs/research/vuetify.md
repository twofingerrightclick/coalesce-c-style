# Vuetify 4 styling and theming internals

Research notes for c-style, the project to restyle Vuetify 4 and the Coalesce `c-` components to match Canon through Vuetify's own customization channels.

**Version baseline.** The reference clone at `.refs/vuetify` sits exactly on tag `v4.3.2` (HEAD `f607e15`, "chore(release): publish v4.3.2"). The demo app declares `vuetify: ^4.0.6`, but `MyProject/pnpm-lock.yaml` resolves it to **4.3.2**, and `MyCompany.MyProject.Web/node_modules/vuetify/package.json` confirms 4.3.2. The source and the installed package are therefore identical. Features added after 4.0, such as `$button-named-sizes` and `$icon-btn-named-sizes` (both 4.3.0), are available. Bumping the floor to `^4.3.0` would make that guarantee explicit. Other installed tooling: `vite-plugin-vuetify` 2.1.3, `vite` 8.3.6, `sass` 1.107.1, `coalesce-vue-vuetify3` 6.5.1.

**Sources.** The docs were read from `.refs/vuetify/packages/docs/src/pages/en/**` at the same tag, which is the source of vuetifyjs.com. Paths below are relative to `packages/vuetify/src/` unless they start with `packages/`.

## 1. Philosophy and architecture

### 1.1 Material-based, token-driven, layered

Vuetify 4 implements Material Design 3: MD3 typography roles, 0–5 elevation, and the `md3` blueprint. It still keeps its own "Vuetify default" look, with 36px buttons, 4px radius and MD3 type. Customization is layered from coarse to fine:

| # | Channel | When applied | Scope | Where |
|---|---|---|---|---|
| 1 | **Blueprint** | `createVuetify({ blueprint })`, deep-merged *under* the rest of the options | Whole app: defaults, theme, icons, locale | `framework.ts` (`mergeDeep(blueprint, rest)`), `blueprints/md1|md2|md3.ts` |
| 2 | **Global defaults** (`defaults.global`, `defaults.VBtn`, nested `defaults.VCard.VBtn`) | Runtime, as props | Per component, per nesting context | `composables/defaults.ts` |
| 3 | **Component props** (`density`, `variant`, `rounded`, `elevation`, `border`, `size`, `color`, `height`…) | Runtime, as classes and inline styles | Per instance | `composables/{density,rounded,elevation,border,size,variant,color}.ts` |
| 4 | **SASS variables** (global `vuetify/settings` and per-component `_variables.scss`) | Build time | Global | `styles/settings/*`, `components/*/_variables.scss` |
| 5 | **Theme** (colors plus `variables`, emitted as CSS custom properties) | Runtime, via an injected `<style>` | Per theme, switchable, nestable via `theme` prop or `v-theme-provider` | `composables/theme.ts` |
| 6 | **Utility classes** (`pa-4`, `rounded-lg`, `elevation-2`, `bg-primary`, `text-body-medium`) | Build time (SASS) plus runtime (theme color classes) | Per element | `styles/settings/_utilities.scss`, `styles/utilities/*` |
| 7 | **Plain CSS** in a known `@layer` | Build time | Anything | `styles/generic/_layers.scss` |

The props in channel 3 mostly compile down to the classes and tokens of channels 4–6. `rounded="lg"` emits the class `rounded-lg` (from `$rounded`). `elevation="2"` emits `elevation-2` (from `$shadow-key` and `$shadow-ambient`). `density="compact"` emits `v-btn--density-compact` (a `$button-density` multiplier times `$spacer`). `color="primary"` emits `bg-primary` or `text-primary`, which are generated by the theme. Changing a token therefore changes every prop that uses it.

### 1.2 Cascade layers (new in v4: always on, five top-level layers)

`styles/generic/_layers.scss`:

```scss
@layer vuetify-core { @layer reset, base; }
@layer vuetify-components;
@layer vuetify-overrides;   // contextual nested styles; "replaces .v-btn.v-btn hacks and most !important"
@layer vuetify-utilities { @layer theme-base, typography, helpers, theme-background, theme-foreground; }
@layer vuetify-final { @layer transitions, trumps; }
```

- All component styles are wrapped through the `tools.layer($name)` mixin (`styles/tools/_layer.scss`). It emits `@layer vuetify-#{$name}` at root, and maps `transitions` and `trumps` to `final.*`.
- The theme stylesheet is generated at runtime as `@layer vuetify-utilities { @layer theme-base {...} @layer theme-background {...} @layer theme-foreground {...} }` (`composables/theme.ts`, `styles` computed).
- Consequence: **any utility class (`rounded-*`, `pa-*`, `elevation-*`, `bg-*`) beats any component rule, whatever its specificity.** That is why props such as `rounded` and `elevation` always win over `$button-border-radius` and similar variables.
- **Unlayered CSS beats all Vuetify layers.** The demo's `src/styles/site.scss` is unlayered. So is `coalesce-vue-vuetify3/dist/coalesce-vue-vuetify.css` (0 `@layer` occurrences).
- The v3 `$layers: true` option is gone; layers are now unconditional. The v3 single layer `vuetify.*` became `vuetify-core`, `-components`, `-overrides`, `-utilities` and `-final` (`packages/docs/.../getting-started/upgrade-guide.md#layers`).
- Custom layer order is documented: put a `public/layers.css` with the full order, *linked* in `index.html` before other CSS, and do not bundle it, because bundle order is unreliable (`packages/docs/.../styles/layers.md`). `vuetify/styles/layers` (`styles/layers.scss`) contains only the order declaration.

### 1.3 Other v4 changes that matter for restyling

From `upgrade-guide.md` unless noted:

- **CSS reset mostly removed.** There is no more global `* { padding:0; margin:0 }`. Native `button`/`input`/`select` keep browser borders and backgrounds, and components normalize themselves. `$reset` (`styles/settings/_variables.scss`) gates what remains (`styles/generic/_reset.scss`).
- **Typography is MD3.** `$typography` keys are `display|headline|title|body|label-{large|medium|small}`. The utility classes `text-h1…text-overline` are gone; the classes are `text-body-medium` and so on.
- **Elevation is MD3, levels 0–5** (it was 0–24). `$shadow-key` and `$shadow-ambient` replace the umbra/penumbra/ambient maps. A new `--v-elevation-overlay` (a registered `@property`) adds a surface tint per level (`styles/utilities/_elevation.scss`, `tools/_elevation.sass`). The prop validator still accepts values above 5, but the classes exist only for 0–5.
- **Breakpoints shrank**: md 840, lg 1145, xl 1545, xxl 2138. Container max-widths round down to 100px.
- **`defaultTheme` is now `'system'`.** Theme colors may carry alpha, so use `rgb(var(--v-theme-x))` or `color-mix(...)` instead of `rgba(var(--v-theme-x), a)`.
- **VBtn**: no uppercase (`$button-text-transform: none`). `$button-stacked-icon-margin` became `$button-stacked-gap`. New `$button-named-sizes` (4.3).
- Removed SASS variables: `$text-field-details-padding-inline`, `$file-input-details-padding-inline` and `$radio-group-details-padding-inline` were replaced by `$input-details-padding-inline`. `$counter-color` was replaced by opacity. `$snackbar-multi-line-wrapper-min-height` and the `multi-line` prop were removed.
- **Grid** uses `gap`. VRow's `dense` became `density`/`gap`; the `align`/`justify` props became utility classes.
- **Style entry points** (`styles/entry-points.md`, `packages/vuetify/package.json` exports): `vuetify/styles` (all), `vuetify/styles/core` (layers, reset, base, transitions; no utilities or colors), `vuetify/styles/colors` (the MD color pack), `vuetify/styles/utilities`, `vuetify/styles/layers`. Each one has a `sass` condition pointing to `lib/styles/*.s[ac]ss`.

## 2. Customization channels in detail

### 2.1 SASS via `vite-plugin-vuetify` `styles.configFile`

```ts
// vite.config.ts
vuetify({ autoImport: true, styles: { configFile: 'src/styles/settings.scss' } })
```

```scss
// src/styles/settings.scss: variables only, no CSS output
@use 'vuetify/settings' with (
  $border-radius-root: 6px,
  $body-font-family: ('Inter', sans-serif),   // parenthesize comma lists
  $button-height: 32px,
  $utilities: (...),                          // allowed here too
);
```

**How the plugin works** (`MyCompany.MyProject.Web/node_modules/vite-plugin-vuetify/dist/index.mjs`, `stylesPlugin`):

- It runs as `enforce: 'pre'` and implements `resolveId`. It intercepts `vuetify/styles`, plus **every `.css` import whose importer lives inside the vuetify package**. Each `lib/components/VBtn/VBtn.js` does `import "./VBtn.css"`.
- `.css` is mapped to the sibling `.sass` or `.scss`. A virtual module `virtual:plugin-vuetify:<file>` is returned with contents `@use "<configFile>"; @use "<component.sass>"`. The settings module is therefore configured once *per compiled Vuetify stylesheet*.
- `configFile` is resolved against `config.root`, or used as given if absolute. **Absolute paths are accepted**, so a package can point it at a file inside its own `node_modules` directory.
- Other modes: `styles: 'none'` (all Vuetify CSS becomes empty modules) and `styles: 'sass'` (compile SASS without a config file).
- Options are captured in a closure when `vuetify()` is called. Another Vite plugin **cannot inject or modify `configFile`** after creation. The ways to ship it are listed in §5.4.

**What `vuetify/settings` is.** `packages/vuetify/_settings.scss` forwards `lib/styles/settings` (global variables) and `dist/component-variables` + `-labs`. Those forward every `lib/components/*/_variables.scss`. A single `@use ... with ()` can therefore set both global and component variables. All variables are `!default`, and component variables derive from the globals (for example `$button-border-radius: settings.$border-radius-root`). Setting a global changes every derived component value unless that component variable is also set.

**`@use 'vuetify' with (...)`** (`main.sass`) can only configure `$utilities`, `$color-pack` and `$reset`, for people not using `configFile` (`sass-variables.md`). It is the same settings module, reached through `@forward './settings'`.

**Using tokens in your own SFC styles:** use `@forward 'vuetify/settings' with (...)` in the settings file, then `@use '@/styles/settings'` and reference `settings.$button-height`.

Documented caveats (`sass-variables.md`#caveats):

- **Settings file must only contain variables, mixins and functions.** Any CSS it emits is duplicated into every Vuetify stylesheet, roughly 100 copies.
- **Build performance**: precompiled CSS is replaced by compiling about 100 SASS files. The docs recommend `sass-embedded` plus the modern compiler API. Vite 7+ uses the modern API by default.
- **pnpm/Yarn symlinks**: if Sass loads `vuetify/settings` via two different real paths, the configuration may silently not apply.

### 2.2 Global SASS variables (`styles/settings/_variables.scss`, `_elevations.scss`, `_utilities.scss`)

| Variable | Default | Feeds |
|---|---|---|
| `$spacer` | `4px` | Spacing utilities (`pa-1` = 4px … `pa-16` = 64px via `$spacers-steps: 16`), **every density delta** (`tools.density` multiplies by `$spacer`), `$size-scale` (= `$spacer*2`), `$grid-gutter` (×6), `$container-padding-x` (×4) |
| `$spacers` / `$negative-spacers` | generated | Overridable maps |
| `$border-radius-root` | `4px` | `$rounded` scale and most component `*-border-radius` defaults |
| `$rounded` | `0:0, sm: root*.5, null: root, md: root, lg: root*2, xl: root*6, pill: 9999px, circle: 50%, shaped: root*6 0` | `rounded-*` utility classes, the `rounded` prop's string values, `*-rounded-border-radius` |
| `$border-width-root`, `$border-style-root`, `$border-color-root` | `thin`, `solid`, `rgba(var(--v-border-color), var(--v-border-opacity))` | `$borders` (`border`, `border-sm|md|lg|xl` classes), component `*-border-*` |
| `$border-opacities` | `null: .12, 25, 50, 75, 100` | `border-opacity-*` classes |
| `$body-font-family` | `var(--v-font-body, 'Roboto', sans-serif)` | `html` font (`elements/_global.sass`) and `$typography` body roles |
| `$heading-font-family` | `var(--v-font-heading, $body-font-family)` | display/headline/title-large roles |
| `$font-size-root`, `$line-height-root` | `1rem`, `1.5` | `html` |
| `$typography` | MD3 15 roles, each `(size, weight, line-height, letter-spacing, font-family)` | `text-<role>` classes and many component font variables (`map.get(settings.$typography, 'label-large', 'size')`) |
| `$font-weights` | thin…black | `font-weight-*` classes |
| `$states` / `$opacities` | `hover: var(--v-hover-opacity)` … | State overlays (§3.1), `opacity-*` classes |
| `$shadow-key`, `$shadow-ambient` (maps 0–5), `$shadow-key-color`, `$shadow-ambient-color` | MD3 | `tools.elevation($z)`, used by `elevation-*` classes and component `*-elevation` |
| `$elevation-overlay-step` | `2%` | `--v-elevation-overlay` tint |
| `$size-scale`, `$size-scales` | `8px`; `x-small:-2 … x-large:2` | Btn/chip/icon `size` prop math |
| `$grid-breakpoints`, `$display-breakpoints`, `$container-max-widths`, `$grid-*` | v4 values | Grid and display (JS thresholds are separate: `createVuetify({ display: { thresholds } })`) |
| `$standard-easing`, `$decelerated-easing`, `$accelerated-easing`, `$transition-duration-root` | MD | Transitions |
| `$utilities` | Map of about 100 utility definitions, or `false` | Helper classes |
| `$misc` | `elevation, hidden, sr-only, pointer-events: true` | Non-`$utilities` helper classes |
| `$color-pack` | `true` | MD palette classes (`text-red-darken-2`…), `styles/generic/_colors.scss` |
| `$reset` | `true` | `styles/generic/_reset.scss` |

**Disabling utilities** (`sass-variables.md#disabling-utility-classes`): use `$utilities: false` for all, or a map of `'<key>': false` (keys are listed in `styles/settings/_utilities.scss`: `margin`, `padding`, `rounded`, `border`, `typography`, `font-weight`, `display`, `flex` and so on), and `$misc: ('elevation': false, …)`. Warning: the `rounded`, `elevation` and `border` **props emit these classes**. Disabling `rounded` or `elevation` utilities silently breaks those props (`useRounded` and `useElevation` only add class names). The **theme** color classes (`bg-*`, `text-*`, `border-*`) are not SASS utilities. They come from `theme.utilities` (runtime), and disabling them breaks every `color` prop (`composables/color.ts` emits `bg-${color}` / `text-${color}`).

### 2.3 Theme object (`composables/theme.ts`)

```ts
createVuetify({ theme: {
  defaultTheme: 'light' | 'dark' | 'system' | name,     // v4 default 'system'
  themes: { light: { dark: false, colors: {...}, variables: {...} }, dark: {...}, myBrand: {...} },
  variations: { colors: ['primary'], lighten: 2, darken: 2 },  // emits primary-lighten-1..
  scope: '#app',        // scope :root vars & classes under :where(#app)
  utilities: true,      // bg-*/text-*/border-* classes (needed by color props)
  stylesheetId, cspNonce, transition,
}})
```

- Custom themes deep-merge over the built-in `light` or `dark` (chosen by `dark: true` or the name `dark`). You only specify deltas.
- **Default colors**: `background, surface, surface-bright, surface-light, surface-variant, on-surface-variant, primary, primary-darken-1, secondary, secondary-darken-1, error, info, success, warning`. `on-*` colors are auto-generated by contrast (`genOnColors`, using `variables['theme-on-dark'|'theme-on-light']`) unless provided. Any extra key, for example `'surface-container'`, gets `--v-theme-<key>`, `bg-<key>`, `text-<key>`, `border-<key>` and an overlay multiplier.
- **Default variables** (light / dark): `border-color #000/#FFF`, `border-opacity .12`, `shadow-color #000`, `high-emphasis-opacity .87/1`, `medium-emphasis-opacity .60/.70`, `disabled-opacity .38/.50`, `idle-opacity .04/.10`, `hover-opacity .04`, `focus-opacity .12`, `selected-opacity .08`, `activated-opacity .12`, `pressed-opacity .12/.16`, `dragged-opacity .08`, `theme-kbd`, `theme-on-kbd`, `theme-code`, `theme-on-code`, `theme-on-dark`, `theme-on-light`, `elevation-overlay-color black/white`, `elevation-overlay-opacity-step 2%`, `highlight-opacity 8%/20%`.
- **Emission** (`genCssVariables`): each color becomes `--v-theme-<key>: r,g,b[,a]` (an **rgb triplet**; use it as `rgb(var(--v-theme-primary))`). Non-`on-*` colors also get `--v-theme-<key>-overlay-multiplier: 1|2` (by luma > .18). **Each `variables` entry becomes `--v-<key>: <value>`**. Values starting with `#` become triplets; anything else is emitted verbatim. Arbitrary keys work too. `variables: { 'font-body': "'Inter', sans-serif" }` sets `--v-font-body` and switches the font at runtime with no SASS. `'shadow-key-opacity'` / `'shadow-ambient-opacity'` tune shadows (`$shadow-key-color` reads `var(--v-shadow-key-opacity, .3)`).
- Output: `:root { color-scheme; --v-* }` for the current theme, plus `.v-theme--<name> { --v-* }` for each theme. All of it goes in `@layer vuetify-utilities.theme-base`, with bg and text classes in `theme-background` and `theme-foreground`.
- **Static (non-theme) CSS variables** set by Vuetify: `--v-theme-overlay-multiplier: 1`, `--v-scrollbar-offset` (`elements/_global.sass`), and `--v-elevation-overlay` (`@property`).

### 2.4 Defaults (`composables/defaults.ts`, `packages/docs/.../features/global-configuration.md`)

```ts
defaults: {
  global: { ripple: false, density: 'compact' },        // any prop name, any component that has it
  VBtn: { variant: 'flat', rounded: 'md', class: 'canon-btn', style: '...' },
  VCard: { VBtn: { variant: 'text' } },                   // contextual (nested) defaults
  VSelect: { VMenu: { VList: { density: 'compact' } } },  // popup content: nest under VMenu/VDialog, not VOverlay
  VPaginationBtn: {...}, VStepperActionsPrevBtn: {...},   // role-named "virtual" keys
}
```

Resolution in `internalUseDefaults`: an explicit template prop wins, then `defaults[ComponentName][prop]`, then `defaults.global[prop]`, then the prop's declared default. `class` and `style` are **merged** (defaults first, then the template), never replaced. They are not allowed in `global`, and for inputs they can leak to inner components.

- **Nested defaults.** Keys starting with an uppercase letter inside a component's defaults are re-provided to its descendants (`provideSubDefaults`, which runs *after* setup). User nested defaults therefore override a component's internal `provideDefaults`. For example, VToolbar provides `VBtn: { variant: 'text' }` (`components/VToolbar/VToolbar.tsx`), and `defaults.VToolbar.VBtn` wins over it.
- **Aliases / virtual components**: `aliases: { CanonBtnPrimary: VBtn }` plus `defaults.CanonBtnPrimary`. Aliases do *not* inherit the base component's default `class` or `style`. The `_as` prop routes defaults lookup.
- `VDefaultsProvider` and `provideDefaults()` scope defaults to a subtree. Options: `scoped`, `reset`, `root`, `disabled`.
- The demo app already sets `VTextField|VTextarea|VSelect|VCombobox|VAutocomplete|VField|VInput: { density: 'compact', variant: 'outlined' }` and `VSwitch: { color: 'primary' }` (`MyCompany.MyProject.Web/src/main.ts`).

### 2.5 Blueprints (`blueprints/*.ts`, `features/blueprints.md`)

A blueprint is just a `VuetifyOptions` object minus `blueprint`: `defaults`, `theme`, `icons`, `locale`, `display`, `aliases` and so on. `createVuetify` does `mergeDeep(blueprint, rest)`, so user options win. There is **one blueprint slot**; to compose, `mergeDeep` manually. `md3` is a good template for a design-system blueprint. It sets `VBtn: { color: 'primary', rounded: 'xl' }`, `VCard: { rounded: 'lg' }`, all text inputs to `variant: 'outlined'`, `VTabs` slider, `VProgress*` `variant: 'split'`, a few theme colors, and the mdi icon set. **A blueprint cannot carry SASS settings**; those must ship separately (§5.4).

### 2.6 Prop-to-token mapping

| Prop | Composable | Output | Underlying token |
|---|---|---|---|
| `density` | `composables/density.ts` | class `{name}--density-{default|comfortable|compact}` | Per-component SASS map × `$spacer` (§3.3) |
| `rounded` | `composables/rounded.ts` | `true` gives `{name}--rounded` (uses `$<comp>-rounded-border-radius`). A string token gives `rounded-<token>` (supports multiple tokens like `"t-lg b-0"`). `0`/`false`/`tile` gives `rounded-0`. A number or CSS length gives inline `border-radius` | `$rounded` |
| `elevation` / `hoverElevation` | `composables/elevation.ts` | `elevation-N` / `hover-elevation-N` | `$shadow-key`/`$shadow-ambient` (0–5 only) |
| `border` | `composables/border.ts` | `true` gives `{name}--border` (thin width, removes shadow). A string gives `border-<tok>` classes | `$borders`, `$<comp>-border-thin-width` |
| `size` | `composables/size.ts` | `{name}--size-{x-small…x-large}`; a number gives inline width and height | `$size-scale`, component size maps |
| `variant` / `color` | `composables/variant.tsx` | `{name}--variant-X`. `color` becomes `bg-<color>` for elevated/flat and `text-<color>` otherwise; a CSS color becomes inline style | `tools.variant` mixin (§3.2) |
| `theme` | `provideTheme` | `v-theme--<name>` class, so a local theme switch | Theme |

### 2.7 Typography

- Global font: set `$body-font-family` / `$heading-font-family` in SASS, **or** set `--v-font-body` / `--v-font-heading` at runtime (theme `variables` or plain CSS). The SASS defaults are `var(--v-font-body, 'Roboto', sans-serif)`, so the runtime route needs no SASS.
- Roles: `$typography` map (merge-able: `$typography: ('body-medium': ('size': .8125rem))` deep-merges). Components read sizes from it at compile time: VBtn `label-large`, VInput `body-large`, VCard title `title-large`, list title `body-large`, table `body-medium`, snackbar `body-medium`, alert title `headline-small`. Changing a role changes those components.
- Some component font sizes are **hardcoded literals**, not role lookups: `$field-font-size: 16px`, `$label-font-size: 1rem`, `$messages-font-size: 12px`, `$tooltip-font-size: .875rem`, `$toolbar-title-font-size: 1.25rem`, `$expansion-panel-title-font-size: .9375rem`, `$list-subheader-font-size`, `$list-item-nav-*`. Set them explicitly.

## 3. Internals

### 3.1 State model: overlay and underlay plus opacity variables

- Interactive components render `<span class="{name}__overlay">` (only if clickable) and `<span class="{name}__underlay">` (`genOverlays` in `composables/variant.tsx`). The overlay is `position:absolute; background-color: currentColor; opacity: 0` (for example `.v-btn__overlay` in `components/VBtn/VBtn.sass`).
- `tools.states($selector)` (`styles/tools/_states.sass`):
  - `:hover` gives overlay `opacity: calc(var(--v-hover-opacity) * var(--v-theme-overlay-multiplier))`
  - `:focus-visible` uses `--v-focus-opacity`
  - `&--active` and `[aria-haspopup=menu][aria-expanded=true]` use `--v-activated-opacity`, plus `+ hover` or `+ focus` when combined.
  - **There is no pressed state in the mixin.** Press feedback is the ripple (`v-ripple`, disable via `ripple: false`). `--v-pressed-opacity` exists but these components don't use it.
- Because the overlay is `currentColor`, the state tint automatically follows text color: on-primary on a filled button, primary on a text button. Theme `variables` (`hover-opacity` and the rest) retune all states globally. `$states` (SASS) can repoint them.
- `--v-theme-overlay-multiplier` is 1 by default. `bg-<color>` classes set it to the color's multiplier, 2 for dark-on-light-in-dark-theme cases, so tints read on any background.
- VBtn focus ring: `::after` with a `2px solid currentColor` border at `opacity: calc(.25 * multiplier)` on `:focus-visible` (`VBtn.sass`). It is CSS only; no variable controls width or offset.
- Disabled VBtn: when `$button-colored-disabled` is true (the default), `opacity: $button-disabled-opacity (.26)`. Elevated/flat variants switch to the `surface` background and `on-surface` text. Other components mostly use `opacity: var(--v-disabled-opacity)` (VField, VInput).
- Elevated hover and active: `$button-elevation: ('default':1,'hover':2,'active':1)`.

### 3.2 Variants (`styles/tools/_variant.sass`)

`@include tools.variant($contained-background, $contained-color, $contained-elevation, $plain-opacity, $name)`:

| Variant | Background | Text | Extra |
|---|---|---|---|
| `elevated` | `$contained-background` (for example `$button-background` = surface) | `$contained-color` | `elevation($contained-elevation)` |
| `flat` | Same | Same | `elevation(0)` |
| `tonal` | transparent | inherit | `__underlay { background: currentColor; opacity: var(--v-activated-opacity) }` |
| `outlined` | transparent | inherit | `border: $border-width-root solid currentColor` |
| `text` | transparent | inherit | Overlay is currentColor (states only) |
| `plain` | transparent | inherit | `opacity: $plain-opacity (.62)`, 1 on hover/focus; overlay hidden |

With `color="primary"`, elevated/flat get `bg-primary` (sets `background-color: rgb(var(--v-theme-primary))`, `color: rgb(var(--v-theme-on-primary))` and the multiplier). The others get `text-primary`, which drives border, overlay and underlay via `currentColor`. **Tonal strength = `--v-activated-opacity`**, shared with the active state, so a separate tonal alpha needs CSS. The outlined border is always currentColor at full opacity; a muted outline needs CSS or `border-color`/`border-opacity` utility classes.

The `$<comp>-variants` lists (`$button-variants`, `$card-variants`, `$chip-variants`, `$alert-variants`, `$list-item-variants`, `$snackbar-variants`, `$icon-btn-variants`) are the per-component hooks for default background, color, elevation and plain opacity.

### 3.4 Field variant internals (`components/VField/VField.sass`, `VField.tsx`)

- `VField` default variant is `filled` (prop default). The variants are `filled | outlined | plain | underlined | solo | solo-inverted | solo-filled`.
- **outlined**: no box border. `.v-field__outline` contains `__outline__start`, `__outline__notch` (gap for the floating label) and `__outline__end`, each with a `border: 0 solid currentColor`. Width comes from `--v-field-border-width` (`$field-border-width: 1px`, `$field-focused-border-width: 2px` when focused). Opacity comes from `--v-field-border-opacity`: `$field-outline-opacity .38` at rest, `var(--v-high-emphasis-opacity)` on hover, `1` when focused. Color is currentColor; the `color` prop sets the focused color. Radius is `$field-border-radius` (root, 4px); with the `rounded` prop it is `$field-rounded-border-radius` (xl).
- **filled**: top corners rounded, bottom 0. The bottom line is `.v-field__outline::before/::after` with width `0 0 var(--v-field-border-width)`, plus a focused 2px line. The background is the `__overlay` at `$field-overlay-filled-opacity .04`, plus hover and focus state opacities.
- **solo / solo-filled / solo-inverted**: `background: $field-control-solo-background` (surface), `elevation($field-control-solo-elevation: 1)`. solo-inverted focused uses `surface-variant`.
- **underlined / plain**: radius 0, no horizontal padding, 48px base.
- **Padding**: `$field-control-padding-start|end: 16px`, `-top: 8px`, `-bottom: 4px`, `$field-control-affixed-padding: 12px`, `$field-control-affixed-inner-padding: 6px`. These become `--v-field-padding-*` CSS variables, which can be overridden per selector.
- **Floating label**: `$field-label-floating-scale: .75`. The notch geometry is computed in JS (`VField.tsx`). There is **no "label above field" variant**; that layout means using `VLabel` outside the field, or CSS.
- Details row (hint, error, counter) belongs to VInput: `$input-details-*` (font .75rem, `min-height 22px`, `padding-inline 16px`, `padding-above 6px`).
- Disabled: `opacity: var(--v-disabled-opacity)`. Readonly has no distinct style; the demo's `site.scss` adds dashed outlines through CSS.

## 5. Gotchas and limits

### 5.1 What needs CSS (no SASS, default or theme hook)
- **Structure and layout**: field label position (floating notch only), field prepend/append icon placement, button content order, data table header background and sort-icon shape, the checkbox and radio glyph shape (comes from the icon font; the alternative is custom SVG icon aliases).
- **States beyond the overlay model**: separate pressed tint (no `:active` overlay rule; ripple only), focus-ring width, offset and color on VBtn (fixed `::after` 2px currentColor at .25), focus rings on fields (fields only thicken the outline), a hover background on outlined fields, tonal alpha separate from `--v-activated-opacity`, outlined border color distinct from text color.
- **Per-state radius**: only VBtn named sizes have `border-radius-pressed`.
- **Hardcoded literals inside `.sass` rules** (not variables). Examples: the `16px` base in `--v-input-padding-top: 16px + mod/2` and the outlined `--v-field-padding-bottom` (`VInput.sass`, `VField.sass`), VBtn icon-size multipliers `18/21` and `24/21`, chip size step `6px`, toolbar density deltas (JS).
- **Font sizes that are literals** (§2.7) are settable but don't follow `$typography`.

### 5.2 Specificity and layers
- Put c-style CSS **inside `@layer vuetify-overrides { … }`**. The layer is predeclared by `vuetify/styles` (`generic/_layers.scss`), so its order is deterministic with no `layers.css` needed, **provided `vuetify/styles` loads first**. Layer order is fixed by first appearance: if c-style's stylesheet is imported or bundled ahead of `vuetify/styles`, `vuetify-overrides` is declared first and lands *below* `vuetify-core`/`-components`. Import c-style CSS after `vuetify/styles`, or prepend the full layer statement to it. Rules there beat `vuetify-components` at any specificity, and lose to utilities, so `pa-*`, `rounded-*` and `bg-*` props still win. Inside that layer, still out-specify Vuetify's own overrides rules (VTable, VListItem, VOverlay, VTab, VTextarea, VExpansionPanel, VTooltip and others use it).
- Unlayered CSS (including Coalesce's `coalesce-vue-vuetify.css` and the demo's `site.scss`) beats every Vuetify layer, including utilities. Unlayered Canon CSS would break `class="pa-2"`-style escape hatches.
- A new top-level layer such as `@layer c-style` declared *after* Vuetify's CSS lands after `vuetify-final`, above utilities. Placing it between Vuetify layers requires the linked `public/layers.css` (bundled order is unreliable, per `styles/layers.md`).
- Theme CSS lives in `vuetify-utilities.theme-base`. Overriding `--v-*` variables in plain `:root {}` (unlayered) works and beats the theme, but it is not theme-switch aware. Prefer theme `variables`, or `.v-theme--light {}`.
- The demo's `vite.config.ts` forces all CSS into one chunk to keep order stable (`codeSplitting.groups[0]`).

### 5.3 Build, HMR and performance of `configFile`
- With `configFile` set, every Vuetify component stylesheet becomes a virtual SCSS module that `@use`s the config file, so each one compiles from source.
- Coalesce imports from the `vuetify/components` barrel (22 imports in `coalesce-vue-vuetify3/dist/components`, each `from "vuetify/components"`), which pulls in every component module in dev. Expect about 100 SASS compiles on cold start.
- Editing the settings file should invalidate every one of those virtual modules (all depend on it), so expect full Vuetify CSS recompilation per save. This is inferred from the plugin design, not measured.
- Mitigations: `sass-embedded`; keep the settings file variables-only (CSS in it gets duplicated into every module); with Vite 8 the modern Sass API is default.
- Not tested: whether the production build tree-shakes unused component CSS when components come in through the barrel. Vuetify's `sideEffects` marks `*.css|*.sass|*.scss|*.vue` as side-effectful, and JS as side-effect free.
- `styles: 'none'` plus your own `@use 'vuetify/styles'` in one SASS entry is the alternative single-compile pipeline. It loses per-component CSS splitting.

### 5.4 Shipping c-style as a package
A design-system package can ship three parts.

1. **Runtime: a blueprint object** (`Blueprint` type from `vuetify`), containing `defaults`, `theme` (`variables` for opacities, `font-body`, shadow opacities; colors left for the app), `aliases` and `icons`. App usage is `createVuetify({ blueprint: canon, ...appOverrides })`. Only one blueprint slot exists, so the package should export it pre-merged or export a `mergeDeep` helper.
2. **Build-time SASS: a settings module**, written as `@forward 'vuetify/settings' with ($border-radius-root: 6px !default, $button-height: 32px !default, …)`. The `!default` inside `@forward … with` keeps it overridable downstream. Apps then either:
   - point `configFile` straight at the package file (an absolute path is accepted, for example `fileURLToPath(import.meta.resolve('c-style/settings.scss'))`), or
   - write their own settings file with `@use 'c-style/settings' with ($button-height: 36px)` to override Canon values.
   A module can only be configured once per compilation, so the app must not also `@use 'vuetify/settings' with (...)` in the same file.
3. **A Vite plugin wrapper**: `export function canonVuetify(opts) { return vuetify({ autoImport: true, ...opts, styles: { configFile: opts.configFile ?? <pkg settings path> } }) }`. It replaces the app's `vuetify()` call. An independent plugin cannot reach into `vite-plugin-vuetify`'s closure to inject `configFile`. The alternative is to reimplement its ~60-line `stylesPlugin` `resolveId`/`load` logic in the package plugin and use `styles: 'none'`/`false` on the official plugin, which is more brittle.
4. **CSS for the gaps** (§5.1): ship plain CSS wrapped in `@layer vuetify-overrides { … }`, imported after `vuetify/styles`. Don't put it in the SASS config file.

Other notes:
- If an app opts out of the SASS step, Canon falls back to runtime-only channels: defaults, theme variables, the `--v-font-*` variables and CSS.
- `$spacer` changes ripple through utilities, density and grid gutters. Keep it at 4px unless Canon's base unit differs.
- `rounded="xl"` means `$border-radius-root × 6`, so redefine `$rounded` to Canon's radius scale rather than only changing the root.
- Elevation props and classes stop at 5. Map Canon shadows into `$shadow-key`/`$shadow-ambient` keys 0–5; extra keys don't generate classes, because the loops are hardcoded `0 through 5` in `styles/utilities/_elevation.scss`.
