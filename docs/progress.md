# Canon parity tracking

The component-by-component review is tracked in the [November 7, 2026 parity checklist](parity-2026-11-07.md). It starts from a complete inventory and records review outcomes, evidence, and accepted differences. An unchecked item is not a claim that the component is broken; it means it has not yet completed this review.

- [Baseline checklist template](parity-checklist-template.md) — copy this for a new review cycle.
- [Parity acceptance criteria](parity-acceptance.md) — how to compare, decide status, and document discrepancies.
- [Historical implementation and milestone log](archive/progress-milestones.md) — retained in full for implementation details, earlier test results, and decisions. Its milestone completion labels and test results are historical, not current parity certifications.
- [November 6 unfinished-work audit](review/unfinished-audit.md) — historical leads to recheck; later code and review results take precedence.
- [Original implementation plan](plan.md) — original scope and design decisions, not a live checklist.
- [Upgrade and test instructions](../DEVELOPMENT.md#upgrading-vuetify-or-coalesce) — maintenance checks when upstream dependencies change.

The checklist is the place for new component-level review results. Keep history: when a review is complete, record its completion date and retain it; start a dated copy of the template for the next review. Do not mark an item complete just because it has a Storybook story, passed a historical test, or was part of a completed milestone.
